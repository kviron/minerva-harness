# Релизы Minerva IDE

Основная ветка — `main` в `kviron/minerva-harness`. Первый установочный релиз
форка — `0.2.0`, Windows x64 (NSIS). Прежний harness сохранён в `clear-harness`.

## Автообновление

Приложение читает
`https://github.com/kviron/minerva-harness/releases/latest/download/latest.json`.
Манифест указывает на установщик и содержит подпись. Публичный ключ Minerva
встроен в приложение; закрытый хранится в GitHub Actions secret
`TAURI_SIGNING_PRIVATE_KEY`. Ключ upstream OpenIDEA не используется.
Для нашего канала зеркало CNB OpenIDEA не добавляется даже при сохранённой
настройке источника CNB. Переменная `OPENIDEA_UPDATE_ENDPOINT` остаётся ручным
переопределением для тестирования.

Локальная резервная копия ключа: `%USERPROFILE%\.tauri\minerva-ide\updater.key`.
Сохраните её отдельно: потеря ключа потребует ручной установки новой версии.
Закрытый ключ и `keygen.log` нельзя добавлять в Git или release assets.
Подпись Tauri защищает автообновления; сертификат Authenticode для Windows
этим релизом не предоставляется, поэтому SmartScreen может показывать предупреждение.

## Следующий релиз

1. В чистом `main` выполните `pnpm release:prepare 0.2.1` (подставьте следующую версию).
2. Выполните проверки затронутого кода и `pnpm build`.
3. Закоммитьте изменения версии и отправьте `main`.
4. Создайте и отправьте тег: `git tag v0.2.1`, `git push origin v0.2.1`.
5. Workflow `Minerva release` соберёт подписанный Windows x64 установщик,
   проверит наличие подписи и `latest.json`, затем опубликует релиз.

Не меняйте существующие теги и ключ подписи для обычного обновления.
При ошибке workflow остаётся draft; после исправления сборку можно повторить
через workflow_dispatch с существующим тегом. Уже опубликованный релиз
исправляйте новой версией.

## Изменения upstream

Обновления исходного OpenIDEA и обновления установленной Minerva — разные процессы.
Для переноса исходников: `git fetch upstream`, отдельная ветка от `main`, затем
`git merge upstream/main`. Разрешите конфликты, сохранив identity `ru.minerva.ide`,
наш update endpoint и публичный ключ, интеграцию Minerva и workflow релиза.
После проверки объедините ветку в `main` и выпустите новую версию по шагам выше.

Настройки debug-сборки из отдельного профиля не переносятся в установленную
release-сборку автоматически. Установленная Minerva использует свой app identifier
и не заменяет установленный OpenIDEA.
