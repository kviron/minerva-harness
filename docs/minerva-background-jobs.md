# Фоновые shell-команды Minerva

Образец поведения — DSH на commit
[`4b399c39`](https://github.com/deepseek-ai/deepseek-harness/tree/4b399c39a6d1479cd84ca591b4d7c88e24d38a96/packages/shell/tool-bash):
один процесс, ограниченное ожидание, передача того же задания в фон, отдельное
чтение вывода и остановка по ID. Реализация адаптирована к Rust и протоколу OpenIDEA.

`shell` принимает `command`, необязательные `run_in_background`, `timeoutMs` и `label`.
Явный фон возвращает `jobId` сразу. Обычный вызов ждёт до 120 секунд по умолчанию
(максимум 600 секунд), затем передаёт тот же процесс сессии. Короткие foreground
вызовы не засоряют список фоновых задач. `job_list` возвращает метаданные,
`job_output` — ограниченный вывод с отдельными byte cursors stdout/stderr,
`job_kill` останавливает только задание вызывающей сессии.

## Владельцы и границы

- `mh-workspace-tools/jobs/process.rs` владеет оболочкой, деревом процессов и трубами.
  На Windows Job Object подключается до передачи команды в stdin; на Unix используется process group.
- `output.rs` хранит ограниченные буферы и обрабатывает разделённые UTF-8 символы.
- `registry.rs` отвечает за ID, принадлежность сессии, лимиты, наблюдение и завершение.
  В нём нет обращений к БД, Rig или UI. Активных заданий максимум 10 на сессию и 64 на runtime.
- `tools.rs` связывает допуск ToolRegistry, ожидание, передачу владения и модельные инструменты.
  До передачи в фон отмена вызова останавливает процесс; после неё завершение хода
  не отменяет задание. Чтение UI не сдвигает курсоры модели.
- Native-адаптер публикует штатные `openidea_background_tasks` и принимает
  `_openidea/stop_task`. Проверяются рабочая область, сессия и владелец задания.
  Последнее отключение native-соединения сессии запрещает поздний запуск и останавливает её процессы.

Запуск команды проходит прежнюю проверку разрешений. ReadOnly запрещает новые
команды, но сохраняет чтение вывода и остановку уже допущенного задания. Понижение
разрешений не отменяет уже начатые эффекты процесса.

UI получает подготовленные данные через общий AgentTask. Бейдж в шапке открывает
панель активных и завершённых заданий: команда, время, раскрытие вывода и Stop.
Clear скрывает завершённые строки только в интерфейсе. Завершённые строки не
удерживают соединение от штатного idle recycling. Буферы, история заданий и
публикуемые снимки ограничены; старый потерянный вывод явно помечается.

Сервис останавливает и дожидается собственных процессов при teardown, даже если
сохранён Arc. Неподтверждённое завершение не объявляется успешным. PID не служит
идентификатором доступа и не используется для восстановления после рестарта.

Автоматический запуск нового LLM-хода при завершении задания и перенос живого
процесса между запусками приложения в этот срез не входят. Модель проверяет
состояние через `job_output`; пользователь видит изменения в панели независимо от хода.
Прежний запрет смены провайдера при активной фоновой работе сохраняется;
для такой смены сначала нужно остановить задания.
